# Style 3: `toon25d` ("2D cartoon characters in a 3D world")

**Source:** [mromidev/claude-animated-shorts](https://github.com/mromidev/claude-animated-shorts), MIT, about 1.3k stars. It's vendored at `assets/styles/toon25d/upstream/`; the pinned commit is in `UPSTREAM_COMMIT`.
**Status:** studied and planned (2026-11-05). Not yet wired into the engine registry.

## 1. What it is
A Claude skill (`SKILL.md`) plus the complete source of one proven short, "The Bridge That Fell for a Song" (67 s). It makes **55–70 s vertical story shorts** with:
- flat, ink-outlined **2D "bean-head" characters drawn in code** (Canvas2D), standing as camera-facing cards (billboards) inside
- a **colourful, painted 3D world** (three.js): a town, houses, Kenney CC0 props, painted textures, black ink outlines, sky shader, fog, river;
- **gliding cameras**, impact shakes, lens blur, bloom and a colour grade;
- **voice narration**, plus **synthesized SFX and an original march-style score**, mixed and ducked.

Everything renders **locally** through **Remotion** (React video) and **@remotion/three**. There's no AI video generator, so it costs nothing per video.

## 2. How it works (upstream pipeline)
| Step | What happens | Upstream files |
|---|---|---|
| 1. Topic and facts | One surprising true story with a visual cause and effect, plus an everyday analogy | `SKILL.md` §1 |
| 2. Script | About 3.7 words/s, 55–70 s, with a fixed beat formula: hook → setting → escalation → snap → deadpan double line → explanation → consequence → callback twist | `SKILL.md` §2, `references/STYLE_BIBLE.md` |
| 3. Voice | `voice.wav` and `words.json` (word timings). Everything is timed to the words | (any TTS or STT) |
| 4. Shot plan | `story.ts`: `SHOTS`, `CAMS` (keyframed cameras), `XFADE`, `FLASH_AT`, `KICKS`, `DOF`, `FOREGROUND`. Reactions land 0–3 frames before their word | `templates/bridge/story.ts` |
| 5. World | Lights and palette, two-tone shading, town building, painted textures, sky, fog, river | `lights.ts`, `shade.ts`, `build.ts`, `paint.ts`, `world.ts` |
| 6. Characters | `Pen` drawing API (600×1000 canvas), bean heads, stick limbs, plum outline, 14 expressions; billboards, crowds, blinks, walk cycles | `toon.ts`, `cast.ts`, `cardshade.ts` |
| 7. Post | ink → lens blur → bloom → neutral tone map → grade (MSAA 4) | `Bridge.tsx`, `ink.ts`, `lensblur.ts`, `grade.ts` |
| 8. Sound | Event table → synthesized SFX and a music score, ducked under the voice, 48 kHz mix | `templates/audio/*.py` |
| 9. Look QA | Stills, side-by-side sheets against references, an Opus verifier | `templates/scripts/*` |
| 10. Render | `npx remotion render … --scale 1.3333` (1440×2560), mux audio, frame-by-frame QA | `short_qa.py` |

**Key insight:** the *look* lives in fixed values (`lights.ts`, `ink.ts`, `grade.ts`, `toon.ts`). The *story* lives in `story.ts` (shots and cameras), `build.ts` (world layout) and `cast.ts` (roles). Each new short = the same look with a new story layer.

## 3. How it fits reelforge
It's a natural third **style engine** behind our existing spine:

```
script/topic ─► performance pass (Claude) ─► performance.json   (shared)
             ─► ElevenLabs auto voice (PR #3) + Whisper words   (shared → becomes words.json)
             ─► toon25d engine:
                  shot-plan generator  → story.ts-style JSON (SHOTS/CAMS/DOF/KICKS…)
                  world/cast presets   → picked from a toon25d asset library
                  Remotion render      → frames/video (1080×1920, scale to 2K)
                  audio/*.py           → SFX + score stems, ducked
             ─► shared finish (captions optional, -14 LUFS, export)
```

**What we reuse from our side:** ElevenLabs auto-voicing, Whisper word timings (exactly the `words.json` it needs), the editor (style picker, script, voice, render queue), the finish and loudness steps, and the project folders.

**What we take from upstream:** the whole look stack, the character drawing API, the camera and shot grammar, the synthesized sound, and the QA scripts.

**What changes:**
1. **Data-driven story.** Upstream hand-writes `story.ts` per short. We define a `toon25d_plan.json` schema (shots, cameras, DOF, kicks, cast roles, set). One Claude call generates it from the performance plus the word timings, and a generic `Story.tsx` reads it. That makes it automatic, which is the owner's goal.
2. **Reusable libraries in place of one bridge:**
   - **Worlds:** the bridge town is one preset. Add presets (city street, school, office, kitchen, space, …) built from the same kit, paint and lights code.
   - **Characters:** a character library on `toon.ts` (hair, outfits, colours, the 14 expressions). The editor's Cast panel lists them.
3. **Captions:** upstream's rule is no captions. For us they're an **option** (on by default for Reels), using our caption renderer.
4. **Script formula:** offered as a *template* in the editor's Script step ("explainer story"), not forced on every video.

## 5. Requirements
- **Node 18+**, plus a Remotion project with `remotion`, `@remotion/three`, `three` and `@react-three/fiber`. It lives in `engines/toon25d/remotion/`.
- Python 3 for `audio/*.py` (numpy or scipy, per the upstream imports; check).
- **Disk:** a Remotion bundle copies `public/` (about 1.3 GB) into temp. Set `REMOTION_TMP` to a large drive.
- **Render time:** measured in the step-1 spike below.

### 5.1 Spike results (2026-11-04, RTX 4060 Laptop 8 GB, Windows 11, Node 24.18)
**Stack (pinned to upstream's `references/reports/CONTEXT.md`):** remotion / @remotion/three / bundler / renderer / cli 4.0.290, three 0.175.0, @react-three/fiber 9.1.2, @react-three/postprocessing 3.0.4, postprocessing 6.37.2, React 19.1. The project is `engines/toon25d/remotion/`. `templates/bridge/` was copied unchanged to `src/videos/bridge/` and `BridgeShort` is registered in `src/Root.tsx`.

**Render time** (1080×1920, full post stack, `gl: "angle"`, jpeg frames, h264 crf 16), from `scripts/spike-render.mjs`:
| What | Time |
|---|---|
| First bundle (webpack) | ~60 s, then ~1 s when cached |
| Still (cold page plus kit and world build plus one frame) | 6.6–7.2 s each |
| Clip, frames 0–149, concurrency 1 | 127.9 s = **0.85 s/frame = 25.6 s per video-second** |
| Clip, frames 0–89, concurrency 3 | 65.4 s = **0.73 s/frame = 21.8 s per video-second** |
| Projection: full 67 s short (2025 frames) at 1080×1920 | about 25–29 min |
| Projection: same at `--scale 1.3333` (1440×2560) | roughly 1.8× the pixels, so expect about 45–50 min (not measured) |

**GPU:** ANGLE runs on the hardware D3D11 path. A still with `gl: "swangle"` (software) took 35.6 s, against 7.0 s with `angle`. Concurrency above 1 gives only about 15%, because the GPU is the bottleneck. Use 2–3.

**Windows issues:**
- None blocking. The bridge rendered first try with no code changes.
- `tsc --noEmit` reports 6 TS2322 errors in `Bridge.tsx` (EffectComposer children typed `Element`, given `Element | null`). The webpack bundle doesn't type-check, so rendering is unaffected. Fix the types in step 2.
- Remotion downloads its own `chrome-headless-shell` (~100 MB, into `node_modules/.remotion`). Upstream's hard-coded Chrome path isn't needed; `browserExecutable: null` works.
- npm 11 skips esbuild's postinstall (`allow-scripts`), but the `@esbuild/win32-x64` binary installs anyway, so the bundler is fine.
- **Kenney props are missing.** The 26 `public/bridge/kenney/*.glb` files (Kenney Nature Kit plus Fantasy Town Kit, CC0) aren't vendored. The loader tolerates 404s, so trees, stalls, banners, lanterns, the windmill and the canoe are simply absent (a procedural tree still shows). The automatic download was blocked by the permission classifier during the spike. **To do:** the owner downloads both kits from kenney.nl and copies the needed `.glb` files into `engines/toon25d/remotion/public/bridge/kenney/` (git-ignored).

**Disk:**
- `node_modules`: 542 MB, including ~240 MB of chrome-headless-shell.
- `REMOTION_TMP=D:/remotion-tmp`: 119 MB after about 8 renders. Without the Kenney kit, `public/` is tiny, so the 1.3 GB per bundle that upstream warns about doesn't happen yet. It will grow once props and audio land in `public/`, so keep `REMOTION_TMP` on D:.
- Outputs: the 5 s clip is 14 MB (crf 16) and a full-res jpeg still is 0.3–0.6 MB.
- C: had 38 GB free and D: had 134 GB free, so D: is the render drive.
